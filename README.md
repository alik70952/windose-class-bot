# Windows Class Bot

برنامه دسکتاپ ویندوزی برای آماده‌سازی اتوماسیون ورود به کلاس‌های آنلاین با رابط کاربری فارسی، Playwright و Google Chrome واقعی.

> وضعیت فعلی: برنامه تنظیمات را ذخیره/بارگذاری می‌کند، رمز عبور را خارج از فایل JSON در Credential Manager/keyring نگه می‌دارد، و با Playwright جریان کامل ورود وادانا، انتخاب درس و ورود به کلاس آنلاین را در Google Chrome اجرا می‌کند.

## امکانات

- رابط گرافیکی فارسی، راست‌چین تا حد ممکن و Dark Mode با CustomTkinter
- فیلدهای نام پروفایل، آدرس صفحه ورود، نام کاربری، رمز عبور، نام کلاس و آدرس اختیاری Adobe Connect
- نمایش/مخفی کردن رمز عبور
- گزینه‌های باز نگه‌داشتن مرورگر، Headless و ذخیره نشست مرورگر
- دکمه‌های ذخیره تنظیمات، بارگذاری تنظیمات، آزمایش بازشدن سایت، شروع ربات و توقف ربات
- اجرای عملیات مرورگر در Thread جداگانه برای جلوگیری از هنگ کردن رابط کاربری
- ذخیره تنظیمات غیرحساس در `config.json`
- ذخیره امن رمز عبور با `keyring` و Windows Credential Manager در ویندوز
- جلوگیری از ورود `config.json` و نشست مرورگر به Git

## پیش‌نیازها در Windows

1. Windows 10 یا 11
2. Python 3.11 یا جدیدتر
3. دسترسی اینترنت برای نصب بسته‌ها و نصب Google Chrome از طریق Playwright

## نصب

در Command Prompt یا PowerShell داخل پوشه پروژه اجرا کنید:

```bat
install.bat
```

این فایل کارهای زیر را انجام می‌دهد:

1. ساخت محیط مجازی `.venv`
2. نصب وابستگی‌های `requirements.txt`
3. اجرای دستور زیر برای نصب Google Chrome مورد استفاده Playwright:

```bat
playwright install chrome
```

اگر Google Chrome قبلاً روی سیستم نصب باشد، Playwright همچنان از `channel="chrome"` برای اجرای Chrome واقعی استفاده می‌کند.

## اجرا

پس از نصب، برنامه را با دستور زیر اجرا کنید:

```bat
run.bat
```

یا به صورت مستقیم:

```bat
.venv\Scripts\activate.bat
python main.py
```

## روش استفاده

1. برنامه را اجرا کنید.
2. فیلدهای ضروری را وارد کنید:
   - نام پروفایل
   - آدرس صفحه ورود با `https://` یا `http://`
   - نام کاربری
   - رمز عبور
   - نام کلاس
3. در صورت نیاز گزینه‌های مرورگر را تغییر دهید.
4. روی «ذخیره تنظیمات» کلیک کنید.
5. برای بررسی مرورگر و سایت، روی «آزمایش بازشدن سایت» کلیک کنید.
6. دکمه «شروع ربات» جریان کامل ورود، انتخاب درس و کلیک روی لینک دقیق «ورود به کلاس» را اجرا می‌کند؛ دکمه «آزمایش بازشدن سایت» فقط برای تست بازشدن URL است.
7. برای بستن مرورگرِ بازمانده، روی «توقف ربات» کلیک کنید.

## امنیت و فایل‌های محلی

- رمز عبور داخل `config.json` ذخیره نمی‌شود.
- رمز عبور با کتابخانه `keyring` در Credential Manager ویندوز یا backend امن سیستم ذخیره می‌شود.
- فایل‌های زیر نباید Commit شوند و در `.gitignore` قرار دارند:
  - `config.json`
  - `browser-session/`
  - `.credentials*`
  - فایل‌های log
- از وارد کردن URL واقعی دانشگاه، نام کاربری، رمز عبور یا اطلاعات شخصی در Repository خودداری کنید.

## ساخت فایل EXE در آینده

PyInstaller در وابستگی‌ها قرار دارد. پس از تکمیل فازهای بعدی می‌توان نمونه دستور زیر را استفاده کرد:

## راه‌اندازی وادانا واحد ۳۹

این نسخه یک Profile محلی آماده با نام «وادانا واحد ۳۹» ایجاد می‌کند. URL ورود از قبل تنظیم شده است، اما نام کاربری و رمز عبور خالی می‌مانند و باید هنگام اجرای برنامه وارد شوند.

1. برنامه را اجرا کنید.
2. Profile «وادانا واحد ۳۹» را انتخاب کنید یا اگر برنامه برای اولین بار اجرا می‌شود همان Profile آماده را بررسی کنید.
3. شماره دانشجویی یا نام کاربری خود را در فیلد نام کاربری وارد کنید.
4. رمز عبور را در فیلد رمز عبور وارد کنید.
5. گزینه «ذخیره امن رمز عبور» را فعال کنید تا رمز فقط در Windows Credential Manager/keyring ذخیره شود.
6. روی «آزمایش ورود به وادانا» بزنید.
7. پس از ورود موفق، مرورگر برای بررسی صفحه درس‌ها باز می‌ماند و برنامه پیام «ورود انجام شد. برای تعریف مراحل انتخاب کلاس، صفحه بعدی را بررسی کنید.» را در Log نشان می‌دهد.

نکات امنیتی:

- رمز عبور هرگز در `config.json` ذخیره نمی‌شود.
- نام کاربری فقط در `config.json` محلی ذخیره می‌شود و این فایل در Git قرار نمی‌گیرد.
- Screenshotهای خطا در `logs/screenshots` ذخیره می‌شوند و این مسیر در Git قرار نمی‌گیرد.
- این مرحله فقط ورود را انجام می‌دهد و هنوز Selectorهای درس، کلاس، جلسه یا Adobe Connect حدس زده نشده‌اند.

## زمان‌بندی کلاس‌ها

این نسخه یک بخش «زمان‌بندی کلاس‌ها» برای انتخاب درس، تعیین روز و ساعت، ورود چند دقیقه زودتر و اجرای آزمایشی اضافه می‌کند. زمان‌بندی‌ها در `config.json` محلی و بدون Password ذخیره می‌شوند و هر زمان‌بندی یک UUID داخلی دارد. برنامه زمان‌ها را براساس ساعت محلی Windows کاربر محاسبه می‌کند؛ برنامه درسی دانشگاه ممکن است تغییر کند و کاربر باید زمان‌ها را بررسی کند.

### سه کلاس اولیه

سه Preset قابل ویرایش داخل برنامه وجود دارد:

- «انس با قرآن کریم» — یکشنبه، 09:15 تا 12:15
- «اندیشه های امامین انقلاب اسلامی و وصایای حضرت امام خمینی(ره)» — شنبه، 13:30 تا 17:30
- «اخلاق اسلامی (مبانی و مفاهیم)» — یکشنبه، 12:30 تا 17:30

Presetها فقط مقدار اولیه هستند. کاربر می‌تواند روز، ساعت شروع، ساعت پایان نمایشی و حتی نام کلاس سفارشی را تغییر دهد. هیچ Course ID حدسی در برنامه ذخیره نشده و درس با متن قابل مشاهده لینک انتخاب می‌شود.

### ورود چند دقیقه زودتر

فیلد «چند دقیقه قبل از شروع وارد شود» زمان اجرای واقعی را از ساعت شروع کم می‌کند. مقدار پیش‌فرض 5 دقیقه است؛ برای مثال 09:15 با ورود 5 دقیقه زودتر در 09:10 اجرا می‌شود. اگر محاسبه به روز قبل برسد، برنامه offset روز قبل را نمایش و برای ثبت زمان اجرا از ساعت محلی استفاده می‌کند.

### Worker دائمی زمان‌بندی

صف زمان‌بندی فقط در `data/scheduler.db` نگهداری می‌شود و `config.json` فقط Profile و تنظیمات عمومی را دارد. برنامه برای هر کلاس Windows Task جداگانه نمی‌سازد. فقط یک Task ثابت با نام `VadanaClassBotWorker` ثبت می‌شود. Trigger آن ورود کاربر به Windows است و Windows در صورت Crash، Worker را با فاصله یک دقیقه دوباره اجرا می‌کند.

Task، Worker مستقل از رابط گرافیکی را با Python بدون پنجره اجرا می‌کند:

```powershell
.venv\Scripts\pythonw.exe -m src.scheduler_worker
```

Worker هر ۱۵ ثانیه Scheduleهای فعال را از `config.json` می‌خواند، موارد رسیده را در Thread مستقل اجرا می‌کند و پس از پایان هر اجرا زنده می‌ماند. حذف زمان‌بندی فقط رکورد محلی را حذف می‌کند و Task ثابت Worker دست‌نخورده می‌ماند. قفل Process مانع اجرای دو Worker هم‌زمان می‌شود و قفل هر Schedule/Profile نیز از اجرای تکراری جلوگیری می‌کند.

### اجرای آزمایشی و ورود به صفحه درس

دکمه «اجرای آزمایشی همین حالا» با تأیید کاربر تلاش می‌کند Profile را بارگذاری کند، Chrome را باز کند، نشست ذخیره‌شده را استفاده کند، در صورت نیاز با رمز ذخیره‌شده در Windows Credential Manager وارد شود، درس انتخاب‌شده را در بخش «درس‌های من» پیدا کند و سپس وارد صفحه درس شود.

Selectorهای استفاده‌شده برای درس:

1. لینک دقیق با نام قابل مشاهده درس
2. متن دقیق درس
3. لینک‌های داخل صفحه/بخش درس‌ها با Normalize فارسی

Normalize شامل ی/ي، ک/ك، فاصله، نیم‌فاصله، پرانتز فارسی/انگلیسی و اعداد فارسی/انگلیسی است. اگر Exact پیدا نشود، برنامه فقط پیشنهادهای مشابه را برای عیب‌یابی گزارش می‌دهد و روی نزدیک‌ترین نام کلیک نمی‌کند. اگر چند نتیجه مشابه وجود داشته باشد، عملیات متوقف می‌شود.

### Link ورود به کلاس و Adobe Connect

در صفحه درس، برنامه ابتدا عنوان صفحه را با نام درس انتخاب‌شده تطبیق می‌دهد و سپس فقط روی لینک «ورود به کلاس» کلیک می‌کند؛ لینک «مشاهده آرشیو جلسات» انتخاب نمی‌شود. اگر کلاس هنوز فعال نباشد، برنامه تا مقدار `class_entry_timeout_seconds` منتظر می‌ماند و Stop Event را بررسی می‌کند.

اگر بعد از ورود لینک یا صفحه Adobe Connect دیده شود و گزینه اجرای Adobe Connect فعال باشد، برنامه فقط Schemeهای معتبر و مسیرهای امن را در نظر می‌گیرد و Dialog امنیتی Chrome یا Windows را دور نمی‌زند. ممکن است کاربر مجبور شود بازکردن برنامه خارجی را دستی تأیید کند. اگر Adobe Connect نصب نباشد، مرورگر باز می‌ماند و برنامه نباید Crash کند.

### روش ذخیره امن رمز

Password در `config.json`، Task Scheduler، Log یا Command Line ذخیره نمی‌شود. رمز فقط از طریق keyring/Windows Credential Manager خوانده می‌شود. اگر رمز ذخیره‌شده در اجرای Background پیدا نشود، عملیات بدون Prompt تعاملی با پیام واضح متوقف می‌شود.

### شرایط روشن یا Sleep بودن کامپیوتر

اگر کامپیوتر کاملاً خاموش باشد، برنامه نمی‌تواند کلاس را باز کند. سیستم باید روشن یا در Sleep قابل‌بیدارشدن باشد، اینترنت و Chrome در دسترس باشند و اگر Adobe Connect لازم است نصب/قابل اجرا باشد. ورود خودکار Windows یا اجرای Task در حساب کاربر باید درست تنظیم شده باشد. Wake the computer به پشتیبانی سیستم و تنظیمات Windows Task Scheduler وابسته است.

### محل Log و عیب‌یابی

Logهای برنامه در UI و فایل‌های محلی زیر پوشه `logs/` نگه‌داری می‌شوند و این مسیر در Git نادیده گرفته شده است. برای عیب‌یابی Task Scheduler، وجود Task، زمان اجرای واقعی، فعال بودن حساب کاربر، دسترسی به Chrome، و ذخیره بودن رمز در Windows Credential Manager را بررسی کنید.

### زمان‌بندی قابل‌اعتماد 12 ساعته روی Windows

فرم «زمان‌بندی ورود خودکار به کلاس» زمان را با سه کنترل محدودشده دریافت می‌کند: ساعت `01` تا `12`، دقیقه `00` تا `59` و دوره `AM` یا `PM`. زمان نمایش‌داده‌شده برای کاربر 12 ساعته است، اما مقدارهای ذخیره‌شده در `ClassSchedule` همیشه 24 ساعته و محلی هستند؛ برای نمونه `class_start_time = "12:00"` و `effective_run_time = "11:50"`.

- `12:00 PM` یعنی 12 ظهر و به `12:00` ذخیره می‌شود.
- `12:00 AM` یعنی 12 شب و به `00:00` ذخیره می‌شود.
- زمان‌بندی براساس ساعت محلی همین رایانه Windows اجرا می‌شود و هیچ منطقه زمانی ثابت یا اینترنتی در محاسبه Task استفاده نمی‌شود.

نمونه‌ها:

1. کلاس: `12:00 PM`، ورود زودتر: `0` دقیقه، زمان Task: `12:00 ظهر`.
2. کلاس: `12:00 PM`، ورود زودتر: `10` دقیقه، زمان Task: `11:50 AM`.
3. کلاس: `12:00 AM`، ورود زودتر: `10` دقیقه، زمان Task: `روز قبل، 11:50 PM`.
4. زمان‌بندی دو دقیقه‌ای فقط در Config ذخیره می‌شود؛ Worker زنده آن را در موعد مقرر می‌بیند و Chrome را بدون نیاز به بازبودن رابط اجرا می‌کند.

Task ثابت Worker با XML امن ساخته می‌شود: `InteractiveToken` برای اجرای Chrome در نشست کاربر، `LogonTrigger`، `StartWhenAvailable=true`، `MultipleInstancesPolicy=IgnoreNew`، اجرای مجاز روی باتری، بدون محدودیت زمانی، و `RestartOnFailure`. Action هیچ `schedule_id`، Password، Cookie، Token یا URL جلسه‌ای ندارد. خطاهای Worker در `logs/schedule-worker.log` ثبت می‌شوند.
